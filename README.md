# AI Micro Learnings

A curated collection of micro learning modules focused on generative AI concepts, tools, and practical implementations.

## Overview

This repository provides bite-sized, hands-on learning experiences for generative AI topics. Each module is designed to be self-contained, allowing you to quickly understand, test, and experiment with specific Generative AI concepts and techniques.

### What You'll Find

- **Focused Learning Modules**: Each folder contains a specific topic with clear explanations
- **Code Examples**: Practical, runnable code samples for each concept
- **Quick References**: Documentation to help you get started immediately

## Repository Structure

| Folder  | Topic   | Description |
| ------- | ------- | ----------- |
| `different-inference-providers` | Inference Providers | Hands-on examples of various AI inference providers and their capabilities across multiple programming languages |

## Contributing

We welcome contributions from the community! Whether you want to add a new micro learning module, improve existing content, or fix issues, your input is valuable.

### How to Contribute

#### 1. Getting Started

Before contributing, please:

- Check existing issues and pull requests to avoid duplicates
- Review the repository structure and existing modules to understand the format
- Consider opening an issue first to discuss major changes

#### 2. Types of Contributions

You can contribute in several ways:

- **New Learning Modules**: Add a new AI topic with examples
- **Improvements**: Enhance existing modules with better explanations or examples
- **Bug Fixes**: Fix errors in code or documentation
- **Documentation**: Improve README files, add comments, or clarify instructions
- **Code Quality**: Refactor code for better readability or performance

#### 3. Contribution Process

1. **Fork the Repository**

   ```bash
   git clone https://github.com/[username]/ai-micro-learnings.git
   cd ai-micro-learnings
   ```

2. **Create a Branch**

   ```bash
   git checkout -b feature/your-feature-name
   # or
   git checkout -b fix/your-bugfix-name
   ```

3. **Make Your Changes**

   - Follow the existing module structure
   - Include clear documentation and comments
   - Test your code examples to ensure they work
   - Update the Repository Structure table if adding new modules

4. **Commit Your Changes**

   ```bash
   git add .
   git commit -m "Add: Brief description of your changes"
   ```

5. **Push to Your Fork**

   ```bash
   git push origin feature/your-feature-name
   ```

6. **Open a Pull Request**
   - Provide a clear title and description
   - Reference any related issues
   - Explain what your changes do and why they're needed

#### 4. Module Guidelines

When creating a new learning module, please include:

- **README.md**: Clear explanation of the topic
- **Code Examples**: Well-commented, working code samples
- **Requirements**: List any dependencies (requirements.txt, package.json, etc.)
- **Usage Instructions**: How to run the examples
- **Learning Objectives**: What someone will learn from this module
- **References**: Links to relevant documentation or resources
- **Gitignore**: Relevant gitignore if its needed

#### 5. Code Standards

- Write clean, readable code with meaningful variable names
- Include comments explaining complex logic
- Test all code examples before submitting
- Keep dependencies minimal and clearly documented
- Use consistent formatting within each language

#### 6. Questions or Need Help?

If you have questions or need guidance on contributing, please:

- Open an issue with the "question" label
- Reach out to the maintainers
- Check existing discussions for similar questions
